Windows タイム サービスの時刻同期間隔を変更する方法

Published Date: 2026-11-19
Active Directory►Windows Time Service
feedback 共有

本記事はマイクロソフト社員によって公開されております。
こんにちは。Windows Commercial Support Directory Services チームです。

今回は、Windows タイム サービス (W32Time) により、NTP クライアントが NTP サーバーに時刻サンプルを要求する間隔の変更方法についてご紹介いたします。

Windows タイム サービスでは、時刻同期方式や同期先に指定したフラグによって、同期間隔の決定に使用される情報が異なります。
そのため、同期間隔を変更する際には、まず現在の構成を確認し、変更対象となる設定を判断する必要があります。

本記事では、同期間隔を制御する各パラメーターの役割と、構成に応じた変更手順についておまとめいたします。

注意:

本記事では、Windows タイム サービスが既定で使用するレジストリ設定をご紹介します。
Windows タイム サービスの設定をグループ ポリシーで設定している場合、既定で使用するレジストリでの設定よりもグループ ポリシーの設定が優先されます。
また、グループ ポリシーで設定した値は、本記事で紹介するレジストリ キーとは別のレジストリ キーの配下に保存されます。
そのため、グループ ポリシーで設定を行われている場合には該当する設定をご確認のうえ、必要に応じて変更してください。
また、Intune の設定カタログや CSP を使用して Windows タイム サービスの設定をポリシーとして配布している場合も、本記事で紹介するレジストリ設定よりポリシーの設定が優先されます。その場合は、Intune 側の該当するポリシーをご確認のうえ、必要に応じて変更してください。
※ 現在、ポリシーで制御されている設定があるかどうかについては、後述の「現在の設定の確認方法」に記載の方法でご確認ください。

Windows タイム サービスの設定に対応するグループ ポリシーのパスは、以下のとおりです。

  • [コンピューターの構成] - [管理用テンプレート] - [システム] - [Windows タイム サービス] - [グローバル構成設定]
  • [コンピューターの構成] - [管理用テンプレート] - [システム] - [Windows タイム サービス] - [タイム プロバイダー] - [Windows NTP クライアントを構成する]

グループ ポリシーとレジストリ設定の関係については、以下の弊社公開情報をご参照ください。

Windows タイム サービスのツールと設定 - ローカル グループ ポリシー エディターの使用

時刻同期間隔を制御する値について

時刻同期間隔を制御する値は、w32tm /query /configuration コマンドで確認できる Windows タイム サービスの時刻同期方式を示す Type と、同期先を示す NtpServer に指定されたフラグによって決まります。
具体的には、各設定に従い、MinPollInterval / MaxPollInterval という値の範囲内で間隔を動的に調整する方式と、SpecialPollInterval という値を利用して秒単位で間隔を指定する方式があります。
まずは各値の役割をご説明し、その後に現在の設定の確認方法と、構成に応じた変更対象の判断方法をご紹介いたします。

時刻同期間隔に関連する主な値は、以下の 3 つです。

値の名前 役割
MinPollInterval ポーリング間隔の下限を指定します。
MaxPollInterval ポーリング間隔の上限を指定します。
SpecialPollInterval 手動で指定した時刻ソースに対するポーリング間隔を秒単位で指定します。
NtpServer のフラグに 0x1 が含まれる場合に使用されます。

MinPollInterval / MaxPollInterval

MinPollInterval と MaxPollInterval は以下のレジストリで設定されています。

これらの値は秒数を直接指定するものではなく、設定値を指数とする 2 のべき乗秒でポーリング間隔を表します。

例えば、MinPollInterval が 6、MaxPollInterval が 10 の場合、下限は 2^6 = 64 秒、上限は 2^10 = 1024 秒となります。
MinPollInterval と MaxPollInterval を利用する場合、Windows タイム サービスは、時刻差や同期の状態などに応じて、この範囲でポーリング間隔を動的に調整します。

SpecialPollInterval

SpecialPollInterval は以下のレジストリで設定されています。

こちらの値は、ポーリング間隔を秒単位で直接指定します。例えば、3600 (10 進数) を指定すると、1 時間に相当します。

ただし、Windows 10 バージョン 1703 以降では、SpecialPollInterval は、MinPollInterval および MaxPollInterval を秒数に換算した範囲内である必要があります。
※ 設定値が範囲外の場合は、範囲内で最も近い値が選択されます。

例えば、MinPollInterval が 6 (64 秒)、MaxPollInterval が 10 (1024 秒) の場合、SpecialPollInterval の値は 64 から 1024 の間である必要があります。
この場合、仮に SpecialPollInterval が、3600 に設定されていたとしても、定期的な時刻同期間隔は、1024 秒となります。
そのため、SpecialPollInterval に設定した間隔でポーリングが行われない場合には、MinPollInterval および MaxPollInterval の値の範囲内であるかご確認ください。

各値の説明については、以下の弊社公開情報でもご案内しておりますので必要に応じてご参照ください。

時刻同期間隔の決まり方

同期間隔の制御に SpecialPollInterval を使用するか、MinPollInterval / MaxPollInterval を使用するかは、先ほど確認した Type と、NtpServer に指定されたフラグに応じて決定されます。
対応を以下の表におまとめしております。

Type NtpServer の
フラグ		 同期間隔を制御する設定
NT5DS - MinPollInterval / MaxPollInterval を使用します。
NTP 0x1 を含まない MinPollInterval / MaxPollInterval を使用します。
NTP 0x1 を含む SpecialPollInterval を使用します。
AllSync 0x1 を含まない MinPollInterval / MaxPollInterval を使用します。
AllSync 0x1 を含む ドメイン階層による同期と手動ピアによる同期の両方を考慮し、
MinPollInterval / MaxPollInterval と SpecialPollInterval を確認します。

※ Type が NT5DS の場合、NtpServer のフラグは同期間隔の決定に使用されないため、表では「-」としています。

フラグはビット単位で組み合わせて指定します。例えば、0x9 は 0x8 (Client) と 0x1 (SpecialInterval) の組み合わせのため、SpecialPollInterval を使用する構成です。
一方、0x8 のみの場合は 0x1 を含まないため、MinPollInterval / MaxPollInterval を使用します。

Type やフラグの詳細については、以下の弊社ブログも併せてご参照ください。

Windows タイム サービスの Parameters レジストリ パラメーターについて

時刻同期間隔を変更する方法

ポーリング間隔を短くすると、同期先への問い合わせ頻度が増加します。多数のコンピューターに設定する際には、時刻精度の要件と同期先・ネットワークへの負荷を考慮し、事前に検証することをお勧めいたします。

MinPollInterval / MaxPollInterval を使用する場合の変更手順

ドメイン階層に従って同期する NT5DS の構成や、手動ピアのフラグに 0x1 を含まない構成では、以下の手順で同期間隔を変更します。

  1. 対象のコンピューターに管理者権限を持つアカウントでログオンし、レジストリ エディターを起動します。

  2. 変更前の値を記録し、変更対象のキーをエクスポートするなど、復元できるよう準備します。

  3. 以下のレジストリ キーに移動します。

  4. MinPollInterval および MaxPollInterval を編集し、目的の値を入力します。例えば、64 秒から 1024 秒の範囲にする場合は、以下のように設定します。

    値の名前 設定値 (10 進数) 対応する間隔
    MinPollInterval 6 64 秒
    MaxPollInterval 10 1024 秒

  5. レジストリ エディターを閉じ、管理者権限でコマンド プロンプトを開きます。
    以下のコマンドを実行し、Windows タイム サービスに設定の変更を通知して反映します。
    こちらのコマンドの代わりに Windows タイム サービスのサービスを再起動していただいても設定を反映できます。

  6. 後述の「変更後の確認方法」に従い、設定内容と同期状態を確認します。

SpecialPollInterval を使用する場合の変更手順

手動ピアのフラグに 0x1 が含まれる場合は、以下の手順で同期間隔を変更します。

ここでは、Type が NTP、対象の手動ピアのフラグが 0x9 である構成を前提に、ポーリング間隔を 3600 秒 (1 時間) にする例をご紹介します。

  1. 対象のコンピューターに管理者権限を持つアカウントでログオンし、レジストリ エディターを起動します。

  2. 変更前の値を記録し、変更対象のキーをエクスポートするなど、復元できるよう準備します。

  3. 以下のレジストリ キーに移動し、MinPollInterval / MaxPollInterval を確認します。3600 秒が上下限の範囲に含まれるよう、必要に応じて値を変更します。

    値の名前 設定値の例 (10 進数) 対応する間隔
    MinPollInterval 10 1024 秒
    MaxPollInterval 12 4096 秒

  4. 以下のレジストリ キーに移動します。

  5. SpecialPollInterval を編集し、10 進数で 3600 を入力します。

  6. レジストリ エディターを閉じ、管理者権限でコマンド プロンプトを開きます。
    以下のコマンドを実行し、Windows タイム サービスに設定の変更を通知して反映します。
    こちらのコマンドの代わりに Windows タイム サービスのサービスを再起動していただいても設定を反映できます。

  7. 後述の「変更後の確認方法」に従い、設定内容と同期状態を確認します。

変更後の確認方法

構成内容の確認

管理者権限のコマンド プロンプトで、以下のコマンドを実行します。

Type、NtpServer のフラグ、および変更した各設定値を確認します。SpecialPollInterval を使用する場合は、MinPollInterval / MaxPollInterval の範囲も併せて確認してください。

コマンドの詳細については、以下の弊社ブログをご参照ください。

Windows Time サービスによる時刻同期の基本と w32tm.exe コマンドについて - Windows Time サービスの構成を確認するコマンド

時刻同期状態の確認

以下のコマンドを実行し、想定した時刻同期先の NTP サーバーと時刻同期が成功していることを確認します。

w32tm /resync /rediscover は、同期先の再探索を行ったうえで時刻同期を行うコマンドです。
w32tm /query /status は、現在の時刻同期状態を確認するコマンドです。
これらのコマンドを実行し、時刻同期が成功することをご確認ください。

各コマンドの詳細については、以下の弊社ブログをご参照ください。
