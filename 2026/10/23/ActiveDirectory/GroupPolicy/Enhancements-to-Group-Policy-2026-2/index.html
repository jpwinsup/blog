Group Policy の強化 (2026.02)

Published Date: 2026-10-23
Active Directory►Group Policy
feedback 共有

こんにちは。Windows Commercial Support Directory Services チームです。

本記事では、2026 年 2 月に公開されたグループ ポリシーの 6 つの強化点についてご案内いたします。
いずれもトラブルシューティングに役立つ機能ですので、ぜひご活用ください。

対象 OS:

  • Windows 11 24H2/25H2: 2026 年 2 月 24 日リリースの更新プログラムで既定で有効になります。
  • Windows Server 2022/2025: 2026 年 6 月 9 日リリースの更新プログラムで既定で有効になります。

(1) GPSVC ログのタイムスタンプ強化

概要:

  • 従来の GPSVC ログには時刻のみが記録されていましたが、今回の機能強化により、日付を含むタイムスタンプが記録されるようになりました。
  • 元情報: Reading GPSVC Like a Crime Novel | Microsoft Community Hub

// 2 月 24 日リリースの更新プログラム適用前のログ

// 2 月 24 日リリースの更新プログラム適用後のログ

(2) registry.pol 破損検出

概要:

  • グループ ポリシーのイベント ID 1096 のエラー内容がより具体的に出力されるようになりました。
  • 元情報: When Group Policy Goes Haywire: Spotting registry.pol Corruption Fast (and other problems too) | Microsoft Community Hub

例 1: registry.pol が破損している場合

// これまでのメッセージ

The data is invalid.

// 更新プログラム適用後のメッセージ

Error during registry file parsing: Invalid file signature

例 2: SYSTEM アカウントに registry.pol へのアクセス権がない場合

// これまでのメッセージ

Access is denied. 

// 更新プログラム適用後のメッセージ

Error during registry file parsing: CreateFile failed with 5

なお、これらのイベントが記録された際の GPSVC ログの出力内容には変更がなく、従来と同じ情報が記録されます。

(3) より詳細なエラー情報

概要:

  • Group Policy Preferences (グループ ポリシーの基本設定、以下 GPP) の診断機能が大幅に改善されました。
  • 従来のイベント ID 4098 でも項目名やエラーコードは確認できましたが、詳細な原因の特定には追加のログ取得が必要となる場合がありました。新たに追加されたイベント ID 4117 では、原因の調査に役立つ、より詳細な情報を確認できます。
  • 元情報:From Guesswork to Clarity: GPP Diagnostics Improve in Windows Server 2025 and Windows 11 24H2 | Mic…

// ID:4098

// ID:4117 (追加されたイベント)

(4) 更新処理の実行元の特定

概要:

  • グループ ポリシーの更新処理の実行元を確認できるようになり、問題の特定が容易になりました。
  • 元情報:Assigning Process Accountability to Group Policy Refreshes | Microsoft Community Hub

グループ ポリシーの更新処理を開始したユーザーやプロセスを確認できるようになりました。

これまでは、グループ ポリシーを手動で更新すると、イベント ID 4004 が記録されていました。

今回の機能強化により、グループ ポリシーのイベント ログ (イベント ID 5321) と GPSVC ログで、手動で更新処理を開始したユーザーやプロセスを確認できるようになりました。

GPSVC(2078.340) 2026-mm-dd hh:mm:ss:fff Server_ProcessRefresh:: bMachine = 0, SID = null, bForceRefresh = 1, bRefreshAllUsers = 0, dwTimeout = 600000
GPSVC(2078.1ea8) 2026-mm-dd hh:mm:ss:fff Machine Broadcast Sent successfully to session 0

GPUpdatePID=5048 SessionID=1 Account="xxxxx\xxxxx"

// グループ ポリシーのイベント ログ (イベント ID 5321)

(5) GPP デバッグ ログの有効化

概要:
GPP デバッグ ログを、ドメインの GPO だけでなく、ローカル グループ ポリシー エディターからも設定できるようになりました。
これまではクライアント OS の [コンピューターの構成] - [管理用テンプレート] - [システム] - [グループ ポリシー] 配下に [ログおよびトレース] がありませんでした。
この機能を利用するには、2026 年 2 月 24 日リリースの更新プログラム (プレビュー)、またはそれ以降の更新プログラムを適用する必要があります。

  • ローカル グループ ポリシー エディター (gpedit.msc) から直接 GPP デバッグ ログを設定できます。
  • 管理用テンプレート (ADMX) を使用して、ローカルで設定できます。
  • 元情報: What’s New in Windows Group Policy Preferences Debug Logging | Microsoft Community Hub

// 2 月 24 日リリースの更新プログラム適用後

(6) Critical Section ロック検出

概要:
外部アプリケーションがグループ ポリシーのセクションのロックを保持し続ける問題を検出し、調査できるようになりました。

  • 例: グループ ポリシーの処理が 10 分間応答しなくなる場合などに、原因を特定できるようになりました。

GPSVC ログを有効にすると、ロックを保持しているプロセスを特定できます。
以下に、調査に役立つログを抜粋してご紹介します。

① gpupdate /force 開始

② Writer ロック競合の発生

③ gpupdate.exe へのエラー返却

0x5b4 は ERROR_TIMEOUT (1460) を示し、gpupdate.exe にタイムアウト エラーが返されています。

④ タイムアウト発生と強制解放

  • PID: ロックを保持していたプロセスの PID
  • プロセス パス: ロックを保持していたプロセスの実行ファイルのパス

⑤ ポリシー適用完了

強制解放後、レジストリ拡張と Security 拡張が正常に処理されています。
